## 五、手工验收步骤（建议 15 分钟）

1. **策略中心**（管理员）：设置中心→跟进策略：系统强制行只读 🔒；把 C 周期 14→10 → [保存全部] → 二次确认 → 提示「命中 N 个客户」；操作日志可见 from/to 快照。
2. **惰性生成**：新建客户，编辑填「当前使用软件=管家婆 + 是否新一代=否（已核实）+ 愿意沟通=是（已核实）+ 软件到期=下月」→ 保存 → 打开任务中心：出现 [到期月度] 徽章任务「软件到期月度跟进（本月）」+ 原因行；刷新页面任务不重复。
3. **来源与排序**：任务页来源筛选切「到期月度」只看月度任务；手工建一个约定任务 → 显示 📌 客户约定 且排最前。
4. **重算**：把该客户到期改到 12 个月后 → 任务页该月度任务显示「已取消」；详情时间线出现「跟进计划已重算 · 原因：软件到期时间更新」。
5. **已过期**：把另一客户到期改到上月 → 任务中心出现「软件到期状态核实」任务（原因行含持续核实文案）。
6. **首页到期卡**：首页「软件到期」入口条四个计数与线索池对应筛选结果一致；点击「已过期」跳转带参列表。
7. **立即生成**（管理员）：任务页 [⚡ 立即生成] → Toast「生成完成：新建 N 条，跳过 M 条」；连点两次第二次新建 0。
8. **权限**：销售账号看不到 [立即生成] 与「跟进策略」页签；GET/PUT 策略 API 均 403。
9. **买断**：到期输入 2099-12（买断）→ 客户走象限周期策略（超半年），不进月度。

2. **计划内的口径落地取舍**：① `follow_up_cycles` 防重唯一约束落地为**部分唯一索引**（仅有效行），替代计划 §3.2 字面的全表 unique——这是 §4.5 防重 #2「完成后索引释放」的必要实现（同月到期从未知→半年→远期→半年反复切换时可再生成）；② cycle_key 加来源前缀（M=月度/G=画像补充，象限=轮次数字），避免同客户同策略同月两类任务撞键；③ 画像补充任务挂系统月度策略行、提前量 3 天为引擎常量（PROFILE_GAP_ADVANCE_DAYS，非跟进周期不属"周期必须可配置"红线范围）；④ 自动任务原因行由来源+客户当前到期状态**派生**（不落列），历史任务的原因文案随客户现状轻微漂移——如需强快照可在 V2.x 加 reason 列。

4. **惰性生成对存量真实数据的即时效果**：上线后首次打开首页/任务页即会为现有客户生成当月应跟任务（含已过期核实任务）——这是产品预期行为；开发库迁移前已做全量备份（.verify/v22-backup）。
